# Amazon Sales Intelligence and Order Prediction

A Streamlit analytics application for exploring the provided sample sales data,
reviewing product demand, and evaluating a one-day-ahead demand model.

> This is a portfolio/demo project. The dataset is sample data, the project is
> not affiliated with Amazon, and forecasts are not inventory guarantees.

## Features

- Executive KPIs, date/category/status/product filters, sales trends, and
  product rankings.
- Data-quality reporting against source rows, including missing/invalid fields,
  excluded rows, and duplicates.
- Privacy-conscious CSV exports that omit customer names, customer IDs,
  locations, and payment details.
- Model evaluation that compares the selected Random Forest against a seasonal
  naive (lag-7) baseline using MAE, RMSE, WAPE, and mean error.
- One-day-ahead prediction with the most recent 14 daily product-demand values
  prefilled and editable.
- Cached data/model loading and a Streamlit theme configured in
  `.streamlit/config.toml`.

## Requirements

- Python 3.11
- Dependencies pinned in `requirements.txt`

## Local setup

From the project root, create and activate a virtual environment, then install
the pinned dependencies:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Train the model and generate its evaluation reports:

```powershell
python train_model.py
```

Run the focused tests and launch the dashboard:

```powershell
python -m unittest discover -s tests -v
streamlit run app.py
```

GitHub Actions runs the unit tests, Streamlit page smoke tests, and Python
compile check on pushes and pull requests.

The model is saved to `models/amazon_demand_random_forest.joblib`; evaluation
metadata and per-product test predictions are saved under `reports/`.
Re-run the training command whenever the source dataset or training logic
changes. Do not commit credentials or secrets.

## Evaluation protocol and current results

Training aggregates daily product demand from `Delivered` and `Pending` orders;
`Cancelled` orders are excluded. Missing product/date combinations are treated
as zero demand. Calendar, lag-1, lag-7, lag-14, seven-day rolling mean, and
product features are used.

Rows are split chronologically into training, validation, and final test
windows. Candidate Random Forest settings are selected on validation MAE. The
final 30-day test window is not used for selection. The deployed model is
refitted on all data available before that test window.

The included dataset currently produced the following held-out results:

| Model | MAE (units) | RMSE (units) | WAPE |
|---|---:|---:|---:|
| Seasonal naive (lag 7) | 6.613 | 8.425 | 48.25% |
| Selected Random Forest | 4.862 | 6.217 | 35.48% |

These results are specific to the included sample and a rolling one-day-ahead
test: each test-day prediction can use observed demand from prior days. They do
not measure a recursive 30-day forecast and do not guarantee future accuracy.
Retrain and review the model card after data or pipeline changes.

## Deploy on Streamlit Community Cloud

1. Push this project, its CSV dataset, and the generated model artifact to a
   GitHub repository. Keep `.streamlit/secrets.toml` and credentials out of
   version control.
2. Create a new app in Streamlit Community Cloud and select Python 3.11.
3. Set the repository entry point to `app.py`.
4. Keep `requirements.txt` and `.streamlit/config.toml` at the repository root.
5. Confirm the dashboard's model status and the model evaluation page after
   deployment. If the model artifact is intentionally omitted, analytics still
   work but demand forecasting is disabled until `python train_model.py` is run
   and the resulting model is deployed.

`joblib` model files use Python pickle serialization. Only load artifacts
generated by this trusted project; never accept or load untrusted model files.

## Notes

- Model scores and operational outcomes can drift; this demo has no live data
  connection, monitoring service, authentication layer, or production SLA.
- The dataset includes customer-like columns. The app avoids displaying those
  fields in analytics exports, but repository owners remain responsible for
  verifying that any data they publish is appropriate to share.
